# Session 分享页（单页 HTML 导出）

创建时间：2026-08-06

状态：参考设计草案

把 ai-sdk 格式的 session JSONL（`<sessionId>.messages.jsonl`）解析、变形为一个可分享、可审计的单页 HTML。本目录只关心最终呈现；解析与中间模型另行设计。

## 定位

这个页面不是聊天记录的复刻，而是**以对话为骨架的工作报告**。三层渐进披露：

1. **概览头**（10 秒）：标题、agent、耗时、按 toolKind 聚合的统计 chip。
2. **成果面板**（回答"改了什么"）：只列写入类文件（read 不进面板），按文件去重、累计净 diffstat；文件多时按目录分组折叠，借用 PR files-changed 的心智模型。顶部聚合行不可折叠。
3. **时间线**（回答"怎么做到的"）：assistant 的 text 回复是叙事主线（serif 渲染），工具调用折叠为 kind 分组 chip；展开一层是清单，再展开是单条 input/output 详情，每条详情带 evidence 指针（messageId + toolCallId）。
4. **审计脚注**：脱敏操作清单、原始 JSONL 的 SHA-256、reasoning 开关（默认隐藏，不删除）。

## 关键决策

- **数据与视图打进同一个文件**：中间模型 JSON 内嵌在 `<script type="application/json">`，页面由内联 JS 渲染。这个 HTML 既是可读报告也是机器可解析的数据。生产实现建议改为导出时预渲染静态 markup（`<details>/<summary>` 折叠，禁 JS 环境可读），JSON 仍随文件内嵌供二次处理。
- **净 diff 视图不做**。JSONL 拼不出净 diff（多次修改互相覆盖），净变更的正确数据源是 git / proposal，成果面板放链接指过去。页面只展示逐次修改的 diff 片段。
- **降级策略**：`locations`、diffstat 都是可选数据（并非所有 agent 提供）。拿不到时组头只显示文件数、文件行只显示修改次数，版式不变。
- **output 截断**：头 30 行 + 尾 10 行 + 完整内容 hash；命令失败的 stderr 例外，保留更多。
- **注入内容剥离**：user message 里 FylloCode 注入的 system prompt 不作为用户发言展示，时间线上以一行灰字标注。

## 规模化呈现（复杂会话）

真实的长会话（30 轮、数百段 text、上千次工具调用）靠五个机制收敛页面复杂度：

- **阶段聚类导航**：轮次多到导航放不下时，sticky 导航按"阶段"组织（需求澄清 → 设计 → 实现 → 测试），不逐轮列链接。阶段可由 turn 边界上的启发式（或导出时让 agent 自己总结）聚类。
- **关键轮全展开、常规轮折叠单行**：只有承载决策/转折/大改动的轮次展示全文与 activity 明细；常规往返轮折叠为一行（轮号 + prompt 摘录 + kind 计数 + 结论一句），点开可看摘要。判定信号：edit 数量、命令失败、方案切换、纯文本决策轮。
- **chip 明细截断**："读取 12 个文件"展开只列前 8 条，尾行"还有 N 条，见原始记录"。
- **轮内 text/tool 交错分段**：长轮的 assistant 输出本来就是 text→tool→text 交错的，按 blocks 顺序渲染，中间叙述天然成为动作分组之间的解说。
- **回退阶段显式标注**：走错的路（实现后整体回退）在阶段头打"已回退"徽标，其改动不计入成果面板净变更，但过程完整保留在时间线——这恰恰是审计价值最高的部分。

## 原型

`prototype/session-share.html` — 自包含单页，零外部依赖，内嵌一份手写样例数据：28 轮的大型重构会话（含方案评审、一次整体回退、测试失败与修复、子任务委派），浏览器直接打开即可。支持亮/暗模式（跟随系统）。

样例数据的 schema 即中间模型的草案，见文件内 `#session-data` 块。注意：概览统计（读取 214、命令 96 等）描述完整记录，时间线明细是节选——生产实现中两者由同一数据源保证一致。
